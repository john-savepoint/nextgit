# NextGit — agent rules

**Corpus first:** `docs/STATE.md` (spine index) → `_bmad-output/specs/spec-next-git-platform/SPEC.md` + companions → `platform/CONTRACT.md` → the research dossiers under `_bmad-output/planning-artifacts/research/` and `research/` when evidence is needed. Read them before proposing work.

**The loop:** Work is decided in the task store (`porting/tasks.db`; CLI `bun porting/tasks.mjs`); `docs/NEXT-ACTIONS.md` is a derived view — never edit it by hand. Run work through `porting/wf-template.ddw.js` (single order) or `porting/wf-batch.ddw.js` (batch). State updates only at boundaries (green gate or recorded block). Commits only from the orchestrator (main thread) — workers never commit. Nothing starts a batch it cannot reconstruct from disk.

**Task store:** queue state lives in `porting/tasks.db` (SQLite, WAL; safe across concurrent bun processes). All queue reads/writes go through `bun porting/tasks.mjs` — read with `next`/`list`, write with `set`/`claim`/`release`, then `view` to regenerate the derived `docs/NEXT-ACTIONS.md` (never hand-edit it). Claim before starting an order (`claim <id> --agent <you>`), release when done or blocked. One writer per file still holds for code; the store serializes itself. Invariants: writes are synchronous BEGIN→work→COMMIT blocks — never hold a transaction across an await (bun:sqlite releases a connection whose `Database` is garbage-collected); batch/queue reads skip live-claimed rows (`claimed_by` filter) — claims are the collision guard, honor them.

**Loop roster (runner v3, 2026-10-06):** every phase spawns its specialist — `plan`→**plan-agent** · `implement`/heal-apply→**wf-implementer** (the only editing role) · `verify`→**wf-verifier** (mechanical, verbatim) · heal-research→**heal-researcher** (read-only proposals) · gate lenses: `security`→**security-reviewer** · `quality`→**senior-reviewer** · `spec-fit`→**reviewer** · `compliance`→**compliance-reviewer** · `resilience`/`resilience-2`→senior-reviewer + reviewer (independent finders) · `parity`→**parity-auditor** · `ux`→**designer** · merged batch gate→**senior-reviewer**. Read-only specialists return schema-validated objects; **the runner persists the artifacts** (plan.md, verify.md, gate-*.md, heal-N-research.md). Lens sets: `DEFAULT_LENSES` (quality/spec-fit/security/resilience) scales up to `FULL_LENSES` (+compliance/+resilience-2, +parity/ux per order). Skill hints ride in the prompts (typescript-professional · verification-before-completion · security-audit · systematic-debugging); recorded skill gaps: compliance/resilience/spec-fit lenses carry their own prompt text (no dedicated skill). All role defs live at `~/.omp/agent/agents/*.md` (additive; `compliance-reviewer` added 2026-10-06).

**Evidence:** every claim carries the command + its verbatim output. "Done" names the check that would red if it regressed.

**Secrets:** never in argv, records, or transcripts. The wrangler OAuth token lives at `~/.config/.wrangler/config/default.toml`; Artifacts repo tokens are minted per-run from it and never committed.

**Flags (read before touching these areas):**
1. **Crash-resume** — runner state is durable only because `porting/runs/<id>/run-state.json` is written every phase; never start a batch you cannot reconstruct from disk. `resume: true` skips phases whose artifacts exist and always re-runs gates; the heal budget counts per invocation (`healsThisRun`), so a resumed run can heal again; the in-flight phase restarts from scratch.
2. **Display masks vs corruption** — the harness redacts secret-shaped text in what you *see*; verify raw bytes on disk before "fixing" a file.
3. **Remote hosts** — none in this loop; the platform is Cloudflare-hosted and reached over HTTPS (no SSH route needed).
4. **Gate budget** — heal rounds: default 3 per order, then record, don't loop.
5. **Skills loading** — pinned load paths in `docs/SKILLS.md`; never hand-place a skill elsewhere and assume it loads.
6. **Redaction of inputs** — if harness display differs from disk bytes, trust disk; stage values via files and reference them by path.
7. **Probe tools before documenting guards** — `jq` on this box is **jaq**: `-c` exits 0 on empty *and* dead input; check pipelines use `-ec`. Never ship a check whose failure-mode claim was not executed.
