# NextGit — agent rules

**Corpus first:** `docs/STATE.md` (spine index) → `_bmad-output/specs/spec-next-git-platform/SPEC.md` + companions → `platform/CONTRACT.md` → the research dossiers under `_bmad-output/planning-artifacts/research/` and `research/` when evidence is needed. Read them before proposing work.

**The loop:** Work is decided in the task store (**bd / beads — Dolt-backed, `.beads/`**; CLI `bun porting/tasks.mjs`); `docs/NEXT-ACTIONS.md` is a derived view — never edit it by hand. Run work through `porting/wf-template.ddw.js` (single order) or `porting/wf-batch.ddw.js` (batch). State updates only at boundaries (green gate or recorded block). Commits only from the orchestrator (main thread) — workers never commit. Nothing starts a batch it cannot reconstruct from disk.

**Task store:** queue state lives in **bd (beads, embedded Dolt)** at `.beads/` — override with `BEADS_DIR` (fixtures/workers rely on this). The legacy `porting/tasks.db` SQLite file is a **frozen archive** (read only by the migration script). All queue reads/writes go through `bun porting/tasks.mjs` (the bd adapter) — read with `next`/`list`/`done-ids`, write with `set`/`claim`/`heartbeat`/`release`/`reclaim`/`upsert`/`activate`, then `view` to regenerate the derived `docs/NEXT-ACTIONS.md` (never hand-edit it). Claim before starting an order (`claim <id> --agent <you>`), `heartbeat <id>` during long work (bd leases are ~5m fixed; `--ttl` is accepted-but-ignored), release when done or blocked. **Close contract:** an ALL-GREEN batch CAS-closes its own rows (evidence = batch dir); a blocked batch leaves green rows claimed for the caller to reconcile; `tasks.mjs set … --status done` on an already-closed row is a no-op. **Canonical ids:** every issue is `nextgit-<slug>`; the adapter accepts bare slugs on input and returns canonical ids on every read — always copy ids from reads (flag 9). Out-of-band edits (orchestrator syncs / cross-worktree mirrors) are writers too: before rewriting a path, check `git status --porcelain -- <path>` in the target worktree — never rewrite a path that is dirty inside an in-flight order's IMPLEMENT→GATE window; if a sync must land anyway, force the affected order's re-verify: delete `porting/runs/<id>/verify.md` and resume, so VERIFY re-runs (`porting/wf-template.ddw.js:185`, `:247`) and all gates re-run (`:279`; resumed runs always re-gate — see the Crash-resume flag) on the post-sync bytes. Invariants: batch/queue reads skip live-claimed rows — claims are the collision guard, honor them; do NOT run raw `dolt` CLI against `.beads/embeddeddolt` while bd is live (journal corruption) — use `bd dolt *` wrappers if manual Dolt ops are ever needed; `bd export` exceeds 1MB at ~670 rows — any externalFileSync against bd needs `maxBuffer: 64MiB` (the adapter already sets it).

**Evidence:** every claim carries the command + its verbatim output. "Done" names the check that would red if it regressed.

**Secrets:** never in argv, records, or transcripts. The wrangler OAuth token lives at `~/.config/.wrangler/config/default.toml`; Artifacts repo tokens are minted per-run from it and never committed.

**Flags (read before touching these areas):**
1. **Crash-resume** — runner state is durable only because `porting/runs/<id>/run-state.json` is written every phase; never start a batch you cannot reconstruct from disk. `resume: true` skips phases whose artifacts exist and always re-runs gates; the heal budget counts per invocation (`healsThisRun`), so a resumed run can heal again; the in-flight phase restarts from scratch.
2. **Display masks vs corruption** — the harness redacts secret-shaped text in what you *see*; verify raw bytes on disk before "fixing" a file.
3. **Remote hosts** — none in this loop; the platform is Cloudflare-hosted and reached over HTTPS (no SSH route needed).
4. **Gate budget** — heal rounds: default 3 per order, then record, don't loop.
5. **Skills loading** — pinned load paths in `docs/SKILLS.md`; never hand-place a skill elsewhere and assume it loads.
6. **Redaction of inputs** — if harness display differs from disk bytes, trust disk; stage values via files and reference them by path.
7. **Probe tools before documenting guards** — `jq` on this box is **jaq**: `-c` exits 0 on empty *and* dead input; check pipelines use `-ec`. Never ship a check whose failure-mode claim was not executed.
8. **`bun -e` false-pass** — bun 1.3.14 silently swallows a synchronous throw that occurs AFTER any sync fs read (node -e exits 1 correctly; Promise.reject is still reported). A check shaped "read file(s), then throw on mismatch" can exit 0. In check pipelines prefer `node -e`, or explicit `console.error(...); process.exit(1)`. Verified 2026-10-06 (epics-author fleet).
9. **Canonical id prefix (bd) — load-bearing, do not "simplify"** — every issue id carries the `nextgit-` prefix. bd classifies a dependency target whose prefix differs from the source's as EXTERNAL (`issueops.IsExternalDepTarget`; prefix = text before first hyphen) and files it in `depends_on_external`, which **never blocks** — cross-prefix slugs silently disabled dep gating (root-caused 2026-10-08; migrated by `porting/migrate-to-bd.mjs` v2 + store rebuild; acceptance = ready-set diff vs legacy store = 0). New ids MUST go through the adapter (`add`/`upsert` canonicalize; bare slugs accepted) — never `bd create` with an arbitrary prefix, and never create two issues whose prefixes differ.
