Three storage classes

Every feature in this design lands in one of three tiers. Fast, cheap tiers see every file; expensive reasoning reads only what needs judgment.

  • semantic tier 1

    Holds the per-file semantic index: classification, type, security level and tags, plus the codebase vector index.

    Serves System-1 models that classify every file cheaply, and semantic traversal — not grep.

  • work tier 2

    Holds workspaces, the task queue, presence, authoring leases, secret-typed files and stashes.

    Serves durable, expiring, frequently-written state; locks are surgical.

  • provenance tier 3

    Holds git-notes, per-worker traces, receipts, previews, screenshots and videos, and push provenance.

    Serves the repo answering for itself — no clone required.

The R2 asset tier — live

Large and binary assets live as content-addressed blobs in the R2 bucket nextgit-asset-blobs. Git carries a pointer, assets/<name>.asset.json, next to the asset it names — the pointer format law (AD-10, FR-47; CONTRACT.md §R2 asset tier).

The pointer renders metadata only: the platform never renders blob bytes, patch text or presigned URLs — the rendering law (CONTRACT.md §R2). blobId is an opaque R2 key; the download route is GET /asset/{blobId} (CONTRACT.md §GET /asset/{blobId}).
