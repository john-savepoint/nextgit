# D4 — Security & Provenance Differentiator Prior-Art Check (Round 2, final)

Scope: (a) file-level secret protection in git platforms; (b) agent provenance/attribution + rationale capture; (c) agent identity/authorization primitives; (d) whether anyone packages all three at platform level.
Method: primary vendor/tool sources read this run. Budget cap reached; remaining items recorded as Leads/Not found rather than guessed.

- CLAIM: Git AI (git-ai-project/git-ai) is an open-source (Apache-2.0, Rust) git extension, ~2.8k stars, that links each AI-written line to the agent, model and prompts. It installs with no per-repo hooks and does not wrap the git binary; it provides `git ai blame`, `git ai stats`, and a VS Code/Cursor/Windsurf/Emacs UI. Prompt/conversation sessions are scanned, redacted, and stored *outside* Git ("fine-grained access control"). | SOURCE: https://github.com/git-ai-project/git-ai | PUBLISHER: git-ai-project | PUB_DATE: unknown (repo README says "2026-07-29" screenshot; active 2025-12 commits) | ACCESSED: 2026-10-02 | CONFIDENCE: high | CLASS: capability

### (c) Agent identity / authorization primitives

- CLAIM: gitsign (Sigstore) does **keyless** commit/tag signing bound to an OIDC identity (GitHub, Google, Microsoft), issuing short-lived Fulcio certs and logging to Rekor transparency log; supports `matchCommitter` verification and token providers including `github-actions`, `spiffe`, `google-workload-identity`, `buildkite-agent`. This binds commits to a *workload/human OIDC identity* — it is generic identity, not a first-class "agent ID". | SOURCE: https://github.com/sigstore/gitsign | PUBLISHER: sigstore | PUB_DATE: unknown (repo; current) | ACCESSED: 2026-10-02 | CONFIDENCE: high | CLASS: capability
- CLAIM (gap): No shipped product was found that binds a commit to a distinct, cryptographically verified **agent** identity at the platform level. Git AI's `agent_id` (tool/id/model) is unsigned metadata on a note; Entire's checkpoint is a trailer ID. Neither is verified against a key or an agent's registered identity. | SOURCE: synthesis of git-ai spec + gitsign + entire docs | PUBLISHER: n/a | PUB_DATE: n/a | ACCESSED: 2026-10-02 | CONFIDENCE: medium (absence-of-evidence) | CLASS: capability

### (d) The combination question

- CLAIM: No product found does **typed secret files + signed agent identity + per-change rationale records** as a single platform-level package. Closest partial cover: Git AI (rationale: prompts/session IDs/notes; no secret typing, no signed identity), gitsign (signed identity; no agent model, no rationale, no secrets), git-crypt (file-level content encryption; no platform ACL/typing, no identity, no rationale). Each solves one leg; the three-way platform bundle is unclaimed. | SOURCE: synthesis of sources above | PUBLISHER: n/a | PUB_DATE: n/a | ACCESSED: 2026-10-02 | CONFIDENCE: high (for the negative, bounded by budget) | CLASS: positioning

## Leads

- Infisical, Doppler, HashiCorp Vault (agent injector), bitnami-labs/sealed-secrets, and "BlackBox"/SOPS-in-git wrappers — runtime/KMS secret delivery; not read this run, likely confirm that secret tooling is out-of-repo and not a git access-control layer.
- Cursor's own attribution/telemetry practices — no primary Cursor doc read this run; unverified.
- Commit trailer conventions: `Co-authored-by` / `Assisted-by` / `Generated-by` — no primary source retrieved this run; only `Entire-Checkpoint` was verified. GitLab's AI-attribution trailers need checking.
- Git AI Teams surface (early access) — watch for whether it adds secret or identity features.
- AgenTag (arXiv 2608.00966) and "A Dataset of Agentic AI Coding Tool Configurations" (arXiv 2605.08435) — behavioral-fingerprint attribution literature.

## Not found

- No code host offering file-level read authorization, schema-only/stubbed secret views, or elevation-to-reveal for secret files (searched, no source; stated as absence-of-evidence, medium confidence).
- No evidence that any host hides secret-file contents from users who hold repository read access; only client-side git-crypt achieves hiding, without revocation or per-user scoping.
- No emerging cross-vendor agent-attribution *specification* beyond Git AI's standard (which is a single-vendor open spec) — nothing from GitLab/GitHub/OpenSSF found this run.
- No platform-level cryptographic binding of commits to a distinct agent identity (only generic OIDC keyless signing via gitsign).
- `Co-authored-by`/`Assisted-by`/`Generated-by` trailer norms: no primary source retrieved this run — treat as unverified.
