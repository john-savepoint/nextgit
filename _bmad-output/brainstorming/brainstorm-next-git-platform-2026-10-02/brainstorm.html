Technique II

Swarm Logic — four laws, zero global truth

The hard problem is not teaching agents to write code. It is letting many of them work on one repository at once without ever seeing each other. Four rules came out raw. Four came out sharp.

Agents that share a repo and cannot see each other need coordination that costs no shared state.

R1Communicate through the work

Agents coordinate through simple, standardised communication.

Claims, status, receipts written onto the shared artifact itself. Any agent orients locally — no hub, no global truth.

R2A denial is a wall

No sandbox-escape attempts. Agents respect the boundaries of their box, and must obey tool directives.

The platform counts retries on forbidden paths, closes them, forces the sanctioned alternative, escalates.

R3Declare before you touch

Collision avoidance with zero global knowledge: a claim before the edit, a receipt when it lands.

Emerged whole from the pass — no user draft — as the mechanism that lets R1 stay local: orientation without a hub.

R4Join, don't restart

If someone already claimed the thing, join instead of starting over — socially: when other forks are visible, prefer reusing their code over regenerating the same thing.

Mechanics deliberately deferred to the build phase. The rule is settled; the enforcement is not.

Technique III

Job to be Done — and the six signals that pay for it

R4 is a social habit. Habits don't survive deadlines. The job below is the sentence that makes join‑don‑restart automatic instead of a habit a team has to remember under pressure.

When I am about to build, the platform should watch my intent against everyone else's work and tell me when to join instead of build.

Facilitation note, kept in the record: the user asked that this stay in plain language — "cards" and "hiring" were flagged as confusing. The term is used here only as the technique's name, never in the sentence.

Intent router · declare, then match

Declare what you are about to build. The platform matches it against the fork ecosystem and pings before work starts. Signals trigger investigation, never auto-decision — the user's own phrase: "then we investigate."

Technique IV

Time Horizon Ladder — and what is left when the nebula is subtracted

Three rungs and one honest shrug. The pass was not about predicting 100 years out. It was about noticing which parts of the far future already exist as prototypes on the near rungs.

Rung 1

Always-on fleets

1 year
  • Context-swapping between background sub-agents becomes constant. Compute is always spinning — GPUs at max, shelf token-saving — and always-on decision agents sit underneath.
  • Frameworks of decision agents, not necessarily LLM-based, that feed and prime the LLMs doing the code work. System‑1 decisions can directly drive CI/CD workflows.
  • A visual, comprehensive workflow representing actual people and tools — moving between rooms and levels of a building, so software feels connected to people rather than to a version-controlled data store.
  • The Agent Office: a 3D virtual environment — agent workstations, GitHub-linked PM, multiplayer, unified task queue, whiteboards, screen-share, VOIP, project floors. Our platform should be the beating heart of it.
the cost objection dissolves. Always-on compute is affordable precisely because the decision layer is cheap. Constant spinning and cost-efficiency reinforce each other — they do not contradict. clarified: Agent Office is the target client — keep the traditional web interface; platform infra plus API designed so 3D worlds can represent it. The office is the flagship 3D client, not the core UI.
Rung 2

Portfolios as a service

10 years
  • Agents hold memory and compute between themselves. Intelligent routing of even basic things. Everything ethereal — neural and diffusion rendering of whole ecosystems, possibly diffusing an entire working piece of software.
  • The endgame: humans stop writing code and stop talking to each other about the build. Agents handle both. Humans orchestrate and monitor agent fleets.
  • Mass-level mergers of company portfolios and their software — "companies as a service." Account-level ecosystem merging, not just individual applications.
Each of these has its shadow on Rung 1, already buildable: will as input → intent-first. agents between agents → per-agent memory, handoffs. portfolios as a service → account-level convergence. diffuse-rendering a working system → the review canvas renders change-sets directly.
Rung 3

Past design reach

100 years
  • Mind-upload and intergalactic transmission. Personalities injected into LLMs as real-time weight changes — ephemeral, temporary, reactive, not prompts. Living inside computers, with will as input. Minds reactive to diffusion generation. Robotics and nanomachines maintaining infrastructure forever.
Your answer, kept verbatim because it is the correct engineering posture: "I really don't know. I don't know how to answer that, let alone how to design for it now." Design for the echoes, not the nebula.
The spine

What survives 1 → 10 → 100

  • Intent as the primary input — not code, not tickets.
  • Always-on decision and coordination layers — cheap, underneath.
  • Inhabited representation — a spatial world you move through.
  • Convergence and merging as the central act — the thing the product is for.
Every one of the four is already in the locked demo. The 100‑year rung changed nothing about the 12‑day build; it only told us which four things not to compromise.

What the client already assumes — and what it therefore demands of us

GitHub is its sole backing store. It polls every 90 seconds — no inbound webhooks. An 11‑entity contract is derivable from its protocol surface: Floor, Worker, Task/Queue, Issue, Pull, PR‑detail, Presence, Whiteboard, Services, Settings, Chat. A platform API mirroring it can drop‑in replace GitHub behind a client adapter.

Its missing pieces are our planned core. H3 no cross‑worker review — platform‑native proposals are the convergence layer. H4 per‑worker provenance. H5 a secrets API per worker. H6 push events instead of 90‑second polling. The client is already waiting for the heart.
